# AVTOPRIDE — правила и контекст проекта

Эти правила обязательны для всех изменений в проекте, включая работу Codex и Claude.

## Проект

Статический каталог автомобилей на HTML, CSS и обычном JavaScript, без сборщика.
- `index.html` — структура страницы и диалоги.
- `css/style.css` — стили и адаптивная верстка.
- `js/data.js` — демонстрационные автомобили, категории и курс BYN.
- `js/app.js` — состояние, фильтрация, разметка и обработчики интерфейса.
- `car.html?id=ID`, `js/detail.js`, `css/detail.css` — детальная страница выбранного авто.
- `js/common.js` — общие функции и галерея; `js/detail-data.js` — дополнительные демоданные.
- `assets/` — локальные изображения и иконки из Figma.

Запуск: `python3 -m http.server 8000 --bind 127.0.0.1`.
Макеты: https://www.figma.com/design/qVLCBn6KQfp0tRM0Fbcygi/Untitled
«Каталог v2» (`1:940`) — категории и боковой фильтр;
«Каталог list» (`1:2`) — строковые карточки автомобилей.
«Каталог (детальная)» (`5:2`) — страница до блока «Вопросы и ответы».

## Обязательные правила кода

1. Использовать осмысленные английские имена: `filteredCars`, `currentPhotoIndex`,
   `renderCarList`. Не использовать `$`, `fmt`, `c`, `s`, `t`, `pg` для основных сущностей.
2. Для переменных и функций — camelCase, для констант конфигурации — UPPER_SNAKE_CASE.
3. Одна функция решает одну задачу. Разделять фильтрацию данных, создание HTML,
   обновление DOM и обработчики событий. Инициализацию держать в `initializeCatalog`.
4. Разметка и стили — БЭМ: `block`, `block__element`, `block__element--modifier`.
   Пример: `car-card__action--selected`. Не вводить общие `is-on`, `active`, `next`.
   Изменять классы согласованно в HTML, JavaScript и CSS; ID/data-* — для поведения.
5. Писать понятные комментарии на русском к логическим разделам, контрактам данных
   и нетривиальным решениям. Объяснять назначение и причины, не пересказывать каждую строку.
6. Использовать читаемые отступы в 2 пробела и многострочные шаблоны HTML.
   Не упаковывать несколько операций или большие обработчики в одну строку.
7. Делегировать события динамических карточек; не создавать повторные слушатели при рендере.
8. Экранировать текст и атрибуты из данных перед вставкой через innerHTML.
9. Сохранять доступность: имена кнопок, клавиатурное управление, aria-состояния,
   фокус в нативных dialog и поддержку prefers-reduced-motion.

## Поведение, которое нужно сохранять

- Каталог и детальная страница без хедера/футера; карточки только строковые.
- Ссылка карточки открывает `car.html?id=ID` в новой вкладке; все данные относятся к выбранному ID.
  Неизвестный ID показывает ошибку, а не другой автомобиль.
- На десктопе 6 категорий в свайпере, остальные доступны прокруткой.
- Фотобанк карточки: `images` — массив URL; `img` — одиночное фото для совместимости.
  При нескольких фото — свайп/стрелки/индикаторы; при одном — без переключателей.
- При ширине до 900px фильтр в диалоге; выше — в боковой панели.
  Переносить один DOM фильтра, сохраняя параметры, сброс и счетчик результатов.
- Не выдумывать отсутствующие фотографии/VIN/даты. Избранное сохраняется в localStorage (`avtopride.favoriteCarIds`) и доступно в правой выдвижной панели.

## Проверка изменений

Выполнять `node --check js/app.js`, `node --check js/data.js`, `git diff --check`.
После изменений поведения проверять фильтры, сортировку, пагинацию, галереи и диалоги
на десктопе и телефоне. Поведенческие тесты: `node --test tests/*.test.js`.
